Share Links

Generación de links temporales para compartir archivos de la bóveda, con control de visibilidad y filtrado por tipo de archivo.

Spring Boot JPA / Hibernate UUID como link Soft delete Integra con CaregiverLink

Contexto y objetivo

El usuario guarda archivos en su bóveda digital (capturas, audios, videos, textos). Este módulo permite generar un link temporal para compartir esos archivos sin necesidad de que el receptor tenga la app, o restringido a sus cuidadores de confianza.

Idea central: el owner crea un link, elige qué tipos de archivo incluir y por cuánto tiempo. El sistema devuelve un UUID que el owner comparte por fuera. Quien abra el link accede a los archivos solo si cumple la política de visibilidad.

Decisiones de diseño clave

Link "congelado" (Modelo A)

El link guarda en la DB qué tipos de archivo incluye. No hay query params para modificar el filtro desde afuera. El link es inmutable.

Visibilidad como enum

PUBLIC, AUTHENTICATED o CAREGIVERS_ONLY. Mucho más expresivo que un booleano y extensible a futuro.

Validación en vivo

Si el link es CAREGIVERS_ONLY, se consulta CaregiverLink en cada request. Si el cuidador fue revocado, pierde acceso al instante.

Soft delete

Los links no se borran, se marcan como REVOKED. Tenés historial de qué se compartió, cuándo y con quién.

Entidad ShareLink 

@Entity
@Table(name = "share_links")
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
public class ShareLink {

    @Id
    private UUID id; // el uuid del link

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "owner_id", nullable = false)
    private User owner;

    @CreationTimestamp
    @Column(name = "created_at", updatable = false)
    private LocalDateTime createdAt;

    @Column(name = "expires_at", nullable = false)
    private LocalDateTime expiresAt;

    @Enumerated(EnumType.STRING)
    @Column(name = "visibility", nullable = false, length = 20)
    private ShareVisibility visibility;

    // CSV: "AUDIO,IMAGE,VIDEO". Null o vacío = todos los tipos.
    @Column(name = "file_types", length = 255)
    private String fileTypes;

    @Enumerated(EnumType.STRING)
    @Column(name = "status", nullable = false, length = 20)
    private ShareLinkStatus status; // ACTIVE, REVOKED, EXPIRED

    @Column(name = "revoked_at")
    private LocalDateTime revokedAt;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "revoked_by")
    private User revokedBy;

    @PrePersist
    public void ensureId() {
        if (id == null) id = UUID.randomUUID();
        if (status == null) status = ShareLinkStatus.ACTIVE;
    }
}

Enums asociados

public enum ShareVisibility {
    PUBLIC,           // cualquiera con el link, sin login
    AUTHENTICATED,    // cualquier usuario logueado
    CAREGIVERS_ONLY   // solo cuidadores aceptados del owner, verificados en vivo
}

public enum ShareLinkStatus {
    ACTIVE,
    REVOKED,
    EXPIRED
}

Explicación campo por campo

Campo Por qué existe
id (UUID) Es el link en sí. UUID v4, imposible de adivinar. No necesita hashing extra.
owner Quién creó el link y dueño de los archivos que se comparten.
expiresAt El owner elige los minutos. Si now() > expiresAt, el link se considera EXPIRED sin tocar la DB.
visibility Define la política de acceso. CAREGIVERS_ONLY se valida en vivo contra CaregiverLink.
fileTypes (CSV) Filtro de tipos. "AUDIO,IMAGE" o null = todos. Se valida contra TypeFile al crear.
status Soft delete. ACTIVE → REVOKED (manual) o EXPIRED (calculado). Nunca se borra.
revokedAt / revokedBy Auditoría de revocación. Consistente con CaregiverLink.

Flujo paso a paso

PASO 1

El owner crea el link

Elige visibilidad, tipos de archivo y minutos de expiración. El sistema valida todo y devuelve la URL lista para copiar. 

POST /api/share-links

Body: {
  "visibility": "CAREGIVERS_ONLY",
  "fileTypes": ["IMAGE", "VIDEO"],   // o null/vacío = todos
  "expiresInMinutes": 60
}

→ Valida que cada tipo esté en el enum TypeFile
→ Valida que expiresInMinutes esté en rango (ej: 5..10080)
→ Crea ShareLink {
    id: UUID,
    owner: usuario autenticado,
    visibility: CAREGIVERS_ONLY,
    fileTypes: "IMAGE,VIDEO",
    expiresAt: now() + 60min,
    status: ACTIVE
  }
→ Devuelve: {
    "url": "https://app.com/share/a3f8-...",
    "expiresAt": "2026-10-07T15:30:00"
  }
PASO 2

Alguien abre el link

El sistema valida expiración, estado y visibilidad. Si pasa, devuelve la metadata del link y los archivos filtrados. 

GET /api/share-links/{uuid}

→ Busca link por id
→ Si no existe → 404
→ Si status == REVOKED → 410 Gone
→ Si now() > expiresAt → 410 Gone (y marca EXPIRED)

→ Validación de visibilidad:
   - PUBLIC:          pasa siempre
   - AUTHENTICATED:   requiere usuario logueado
   - CAREGIVERS_ONLY: requiere usuario logueado Y
                      existe CaregiverLink {
                        protectedUser = link.owner,
                        caregiver = currentUser,
                        status = ACCEPTED
                      }
                      Si no → 403 Forbidden

→ Devuelve metadata del link + archivos filtrados por fileTypes
PASO 3

El owner revoca (opcional)

En cualquier momento el owner puede cortar el acceso. No se borra, se marca como revocado. 

PATCH /api/share-links/{uuid}/revoke

→ Verifica que el solicitante sea el owner
→ status = REVOKED, revokedAt = now(), revokedBy = owner
→ A partir de este momento, cualquier GET devuelve 410 Gone

Endpoints del módulo

Método Endpoint Acción Quién
POST /api/share-links Crear link Owner autenticado
GET /api/share-links/{uuid} Ver metadata + archivos del link Según visibility
GET /api/share-links Listar mis links Owner
PATCH /api/share-links/{uuid}/revoke Revocar link Owner
GET /api/admin/share-links Listar todos (admin) Admin

Nota: no hay query params en el GET del link. El filtro de tipos está guardado en la DB (Modelo A). El link es inmutable.

Validación CAREGIVERS_ONLY

Esta es la parte que conecta ShareLink con CaregiverLink. La validación se hace en vivo en cada request, no se cachea ni se congela. 

private void validateAccess(ShareLink link, User currentUser) {
    switch (link.getVisibility()) {
        case PUBLIC -> { /* sin restricción */ }

        case AUTHENTICATED -> {
            if (currentUser == null) throw new UnauthorizedException();
        }

        case CAREGIVERS_ONLY -> {
            if (currentUser == null) throw new UnauthorizedException();

            boolean isCaregiver = caregiverLinkRepository
                .existsByProtectedUserAndCaregiverAndStatus(
                    link.getOwner(),
                    currentUser,
                    CaregiverLinkStatus.ACCEPTED);

            if (!isCaregiver) throw new ForbiddenException();
        }
    }
}

Por qué esto importa: si el owner revoca a un cuidador en el módulo Caregiver, ese cuidador pierde acceso inmediato a todos los ShareLinks con visibilidad CAREGIVERS_ONLY. No hay listas congeladas que puedan quedar obsoletas.

Filtrado por tipo de archivo

El campo fileTypes guarda un CSV de valores del enum TypeFile. Al leer el link, se parsea y se filtra la query de archivos del owner. 

// Parseo seguro del CSV (valida contra el enum)
Set<TypeFile> types = parseFileTypes(link.getFileTypes());
// null o vacío → todos los tipos

// Query de archivos del owner
List<StoredFile> files = (types.isEmpty())
    ? storedFileRepository.findByUser(link.getOwner())
    : storedFileRepository.findByUserAndTypeFileIn(link.getOwner(), types);

// Se devuelven al cliente agrupados por tipo (opcional)
Map<TypeFile, List<StoredFile>> grouped = files.stream()
    .collect(Collectors.groupingBy(StoredFile::getTypeFile));

El parseo ignora valores desconocidos y loguea warning. Nunca lanza excepción por un CSV viejo.
